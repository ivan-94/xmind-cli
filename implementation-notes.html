Current Design Decisions

  • 实现继续以公开 CLI 集成测试驱动，所有 PLAN slice 必须先证明 RED，再用最小实现变绿，最后跑质量门。
  • 读操作和 mutation dry-run 使用统一 JSON envelope；错误码、退出码 和可重试建议以 agent-readable contract 为准。
  • XMind 写入路径使用先生成候选文件、校验、再替换的事务式语义； 保留未知 JSON 字段和未知 package entries。
  • Markdown tree input 支持 frontmatter、heading/list/ordered/task/hybrid outline、note mapping 和行号诊断；inline metadata 当前明确拒绝。
  • --markdown-mode 是严格枚举；heading 拒绝列表项，list 拒绝 heading，hybrid 与 auto 共享当前解析器。
  • Patch 文件读取按扩展名分派：.yaml/.yml 走 YAML， .json 走 JSON，避免 JSON patch 被 YAML 兼容性误接受。

Active Deviations

  • add-tree --apply 尚未实现；当前 tree input 的完整行为主要 通过 dry-run diff 验证。

  • Markdown inline metadata 未解析，只返回 invalid_tree_input。需要引入明确 grammar 后才能支持。

Current Risks

  • src/app/mod.rs 仍然过大。已开始将 patch 文件读取拆到 src/app/patch.rs，并将 tree input / Markdown parsing 拆到 src/app/tree_input.rs。后续应继续拆其他命令 renderer，避免继续在单文件堆叠。
  • Patch engine 后续多个 PLAN 项高度相关。可以合并成小 slice，但每个 slice 应保持约 500 行代码以内，并用公共 CLI 行为测试覆盖。
  • 当前质量门需要通过 Homebrew rustup 路径运行： PATH=/opt/homebrew/opt/rustup/bin:$PATH ./scripts/quality-gate.sh。

Open Questions

2026-05-22 Slice Notes

  • 当前 slice 实现 Parse patch JSON，并把 patch 文件读取逻辑 从 src/app/mod.rs 拆到 src/app/patch.rs。
  • 这个 slice 同时压缩本文件，删除已经完成且不再构成风险的历史流水账。
  • Patch alias delete_tree, move_tree, clone_tree 会分别规范化为 delete, move, copy。
  • Patch precondition ops assert_exists 和 assert_not_exists 只影响校验结果，不产生 diff； 失败时会携带 operation_index 和 canonical operation。
  • Patch add 当前实现 dry-run 规划：校验 parent path 和 非空 title，输出单条 added diff，不写 workbook。
  • Patch set 当前实现 dry-run 规划：校验 node 和 fields， 支持 title/note/labels/markers/hyperlink/image 字段类型检查，并输出 updated diff；实际写入仍等待 patch apply slice。
  • src/app/mod.rs 重构 first pass 已将 patch dry-run planning 与 tree input / Markdown parsing 移出主模块；CLI 行为由 add_tree_test 和 patch_test 做回归保护。
  • Patch replace_tree 当前实现 dry-run 规划：非 root target 会输出旧子树 deleted diff 与新树 added diff；root target 按 mutation root rule 返回 invalid_patch。
  • Patch merge_tree 当前实现 dry-run 规划的默认 match_by: title_path：匹配到的主题在输入 metadata 发生变化时输出 updated diff，缺失子树输出 added diff；prune 和其他 match_by 策略仍按 PLAN 后续任务处理，当前会返回 invalid_patch，避免生成不准确计划。
  • Patch delete 当前实现默认删除子树的 dry-run 规划，并输出每个被删除主题的 deleted diff； children_only 与 promote_children 仍按 PLAN 后续任务处理，当前会返回 invalid_patch。
  • Patch move 当前实现 dry-run 规划，并将 moved diff 表达为 {event, from, to}，而不是 path-only 事件； position 解析和“不能移动到自身/后代”冲突规则复用现有 xmind move 行为。
  • Patch copy 当前实现默认复制子树的 dry-run 规划，输出 copied subtree 的 added diff； preserve_ids: true 沿用现有同 workbook duplicate-id 冲突规则，返回 patch_conflict。
  • Patch ensure_path 当前实现 dry-run 规划：解析不带 path: 前缀的 canonical path，并只为缺失路径段输出 added diff；已存在路径会产生零 diff 的 planned operation。
  • Patch sort_children 当前实现 direct children 的 by: title / order: asc|desc dry-run 规划；排序会改变顺序时用目标节点的 updated diff 表示，recursive: true 仍返回 invalid_patch。
  • Patch set_tree_metadata 当前实现 add_labels dry-run 规划；recursive: true 会遍历目标子树，并只为缺少 任一目标 label 的主题输出 updated diff。其他 metadata patch 字段尚未进入文档化输入范围。
  • Patch delete 已支持 children_only: true dry-run 规划：保留目标主题，仅为 descendants 输出 deleted diff。
  • Patch delete 已支持 promote_children: true dry-run 规划：目标主题输出 deleted diff，直接 children 输出 {event, from, to} moved diff。
  • Patch copy 的 preserve_ids: true 当前按同 workbook duplicate-id 风险处理，返回 patch_conflict；preserve_ids: false 是默认复制路径。
  • Patch merge_tree 已支持 prune: true dry-run 规划：在 title_path 匹配范围内，未被输入 tree 匹配的 existing descendants 会输出 deleted diff。
  • Patch merge_tree 的默认和显式 match_by: title_path 已覆盖；它按相对 title path 匹配 existing topics，匹配节点可输出 updated， 缺失节点输出 added。
  • Patch merge_tree 已支持 match_by: id dry-run 规划；输入 tree 的每个节点必须带 id，否则返回 invalid_patch 和对应 field_path。
  • Patch merge_tree 已支持 match_by: path dry-run 规划；为此 tree input DTO 接受 per-node path 字段，值为 canonical absolute topic path，例如 /Q2/Payment。
  • Patch merge_tree 已支持 match_by: title dry-run 规划；当前按同一 parent 下的 sibling title 匹配，与 title_path 在无重复 sibling title 时行为一致。
  • Patch 操作级诊断已统一到可机器定位的字段路径：涉及具体 op 字段的错误会返回 operation_index、operation 和形如 ops[1].node 的 field_path。
  • Patch 冲突检测已覆盖“前序 delete/prune 计划删除的路径被后续 op 再次引用”的 dry-run 场景；这会返回 patch_conflict 并指向后续 op 的 selector 字段。
  • Patch dry-run 现在使用内存 working copy 顺序规划操作；后续 op 的 selector 会看到前序 op 已创建、重命名、删除、移动或合并后的主题。 该行为只影响规划与诊断，patch --apply 写回仍未开放。
  • Patch dry-run 已加入快照回归覆盖，当前重点固定多 op working-copy JSON 输出结构，防止 summary、operations 与 diff envelope 发生无意漂移。
  • Patch idempotency 已开始落到行为测试：set 写入与当前主题相同的字段值时不再产生 updated diff。
  • export --format json 已输出原始 JSON payload，当前复用 tree payload 结构（sheet + root）。其他 export 格式和文件输出仍在后续任务中实现。
  • export --format markdown 当前输出 heading outline，仅包含主题 title 层级；notes/metadata 的导出开关尚未接入 CLI。
  • export --format outline 输出两空格缩进的纯文本标题树， 用于比 Markdown 更紧凑的人工/Agent 浏览。
  • export --format text 当前作为默认人类可读导出，复用 outline 的缩进标题树格式。
  • export --format assets 当前输出 workbook resource id 列表；实际将资源文件写入目录仍依赖后续 --output 任务。
  • export --output 已支持将当前 export payload 写入新文件； 默认仍拒绝覆盖既有目标并返回 write_failed。 调用方可以显式传入 --overwrite 替换既有文件。
  • export --json 对 stdout 导出使用标准成功 envelope， 原始导出内容放在 result 字段中；当同时使用 --output 时，stdout envelope 只报告写入路径。
  • import --output 已支持从 YAML/JSON tree input 创建新 workbook；.md/.markdown 输入会复用 Markdown outline parser。当前切片仅支持 --apply， dry-run 和覆盖既有输出仍由后续任务处理。
  • import --into 已支持将输入树追加到既有 workbook 的 --parent 选择器下；未传 --parent 时默认使用 root。当前采用 append-last 语义，尚未暴露 position 选项。
  • import --overwrite 目前作用于 --output 创建新 workbook 的路径：默认拒绝覆盖既有文件，显式传入时替换目标。 对 --into 导入既有 workbook 的场景不改变语义。
  • import --output --dry-run 已解析和校验输入并返回 summary，但不会创建目标文件；creation diff 以空 workbook 为基线， 从新根路径 / 开始列出 added 事件。
  • 已增加 Markdown outline 的 export → import round-trip 覆盖： 当前验证主题标题层级往返；notes/metadata/assets 的往返仍取决于后续导出扩展。
  • overwrite 行为已有成对回归测试：默认拒绝覆盖并保留既有目标， 显式 --overwrite 时才替换 export/import output。

Phase 13 - Assets and Images

  • 已建立 topic image 支持类型检测：当前按内容识别 PNG、JPEG、GIF 和 SVG，并已接入 set --image。
  • 图片 checksum 采用 sha256:<hex> 形状，作为后续 asset metadata 与导出清单的稳定标识。
  • set --image 已可将本地 PNG/JPEG/GIF/SVG 作为 topic image 写入 resources/ 并更新 topic 引用；当前 asset id 采用 xap:resources/<file-name>，同名资源会被替换。命令编排放在 src/app/set_image.rs，避免继续扩大 src/app/mod.rs。
  • 替换已有 topic image 时只更新 topic 引用并加入新资源；旧资源按 reference-only 约定保留在 workbook 中，后续如需清理应通过显式 cleanup 设计处理。
  • set --clear image 采用同一 reference-only 语义：只移除 topic 上的 image 引用，不删除 workbook 中已有的 resources/ 条目。
  • 当本地图片文件名与 workbook 中未关联资源同名时，新的 topic image 会使用 sha256 前缀生成不冲突的 resources/ 路径，避免覆盖无关资源。 只有目标 topic 原本就引用同一 asset id 时，才允许同名资源替换。
  • export --format assets --output <dir> 会导出 workbook 中的 resources/ 原始文件，并保留资源目录结构；不带 --overwrite 时仍拒绝覆盖已有输出路径。
  • 不支持的本地图片内容会返回 unsupported_asset_type，JSON 模式下保持标准错误 envelope，退出码为 11。
  • topic-image.xmind fixture 现在覆盖 get、 tree --include-assets、inspect 与 asset export 路径。
  • asset preservation 测试同时覆盖同名 resources/ 冲突与未知 package entry，例如 metadata.json，确保图片写入不会丢失无关条目。
