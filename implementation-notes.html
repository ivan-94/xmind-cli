Current Baseline

  • 当前 CLI 是单 binary Rust package，公开入口由 clap subcommands 驱动；JSON envelope、错误码、退出码和 candidate 诊断是 agent contract 的稳定核心。
  • 读命令、sheet/topic selector、query、compact JSON、单点 mutation、 backup/restore、import/export、topic image 和 asset export 已有代码与 CLI 测试覆盖。
  • 已实现的写路径使用候选文件校验后替换，并保留未知 JSON 字段和未知 package entries；dry-run 不写文件。
  • Tree input 支持 YAML/JSON 与 Markdown frontmatter、heading/list/ordered list、task list、hybrid outline 和 note mapping；Markdown inline metadata 仍是明确拒绝，而不是部分支持。
  • Patch engine 已覆盖 dry-run working copy 规划、operation-indexed diagnostics、alias normalization、conflict detection，以及文档化 patch ops；但写回仍未开放。
  • 文档同步测试覆盖 help surface、schema docs、可运行示例、错误码和若干 stale CLI surface；其中可运行文档示例现在只执行明确标记为 bash e2e 的 fenced block，普通 bash 示例仍为说明性文本。它们不能替代逐命令行为验收。
  • CI workflow、security job、release build smoke、completion、installation docs 和 changelog 均已存在；本地质量门仍以 ./scripts/quality-gate.sh 为准。
  • Canonical remote 已确定为 git@github.com:ivan-94/xmind-cli.git，该 GitHub 仓库已存在且为 public；正式 issue tracker 切换为 GitHub Issues。
  • E2E 定义为用户维度测试：基于真实 .xmind 文件覆盖所有命令和用户可见分支； 第一版使用 Rust integration test runner，release 只做薄 smoke。

Active Deviations

  • add-tree --apply 尚未实现；当前 tree input 的完整行为主要 通过 dry-run diff 验证。
  • patch --apply 尚未实现；Phase 11 当前仍以 dry-run patch engine 为主。
  • diff 目前只注册在 clap subcommand 和命令参考中，dispatch 仍走 noop action；因此 xmind diff --json 不会输出文档中的 summary/changes envelope。
  • validate --strict 当前只验证 workbook 能被读取，并固定返回 valid: true、空 warnings/errors；尚未实现命令参考列出的 topic id、排序、required fields、unknown preservation 等完整检查。
  • import --into 文档称应遵循 normal mutation backup 规则，但 clap surface 没有 --backup，应用层也以 backup: false 运行。
  • PLAN.md 的部分 checkbox 和 Definition of Done 已按历史进度 标记完成，但从文档全量实现角度看过度乐观；真实剩余范围已整理到新的 post-audit slice。
  • GitHub 发布、branch protection、Homebrew tap、README 用户入口和完整 E2E 覆盖仍只是计划，尚未实现。

Current Risks

  • 当前文档同步测试偏向 help/schema/stale-surface 检查，不能发现 diff noop、validate shallow success、 patch --apply 拒绝等行为级缺口；新 slice 需要先补红灯测试。
  • bash e2e 文档示例通过系统 bash 执行，并在临时 PATH 中暴露当前构建的 xmind binary。CI runner 需要提供 bash；当前 GitHub Ubuntu runner 满足该要求。
  • add-tree --apply 和 patch --apply 很容易各自复制 写入逻辑。后续实现应复用 tree input、patch working copy、transactional writer 和 backup 路径，避免 dry-run 与 apply 规划分叉。
  • validate 的范围需要谨慎收敛：先实现文档列出的结构完整性 检查，不要在同一 slice 扩展到未文档化的 XMind 视觉/布局验证。
  • src/app/mod.rs 仍然过大。已开始将 patch 文件读取拆到 src/app/patch.rs，并将 tree input / Markdown parsing 拆到 src/app/tree_input.rs。后续应继续拆其他命令 renderer，避免继续在单文件堆叠。
  • Patch engine 后续多个 PLAN 项高度相关。可以合并成小 slice，但每个 slice 应保持约 500 行代码以内，并用公共 CLI 行为测试覆盖。
  • 当前本机 Homebrew Rust 无法加载 /opt/homebrew/opt/llvm/lib/libunwind.1.dylib，导致 cargo 直接 abort；在修复工具链前，无法给出新的本地质量门证据。
  • 发布流程计划使用 cargo-dist/dist。这能降低多平台 release artifact 维护成本，但需要单独审查生成的 workflow，避免引入过重或不透明的发布步骤。
  • Homebrew tap 涉及第二个仓库 ivan-94/homebrew-tap，应独立于首个 GitHub Release artifact 交付，避免一次性调试两个发布面。
  • Real XMind App golden fixtures 仍是人工门控。2026-05-23 已确认 /Applications/Xmind.app 存在且版本为 26.02.04171， 但没有 AppleScript scripting definition；GUI Save As 路径未能可靠地在 worktree 创建文件。不得把 synthetic fixture 标记为 real-xmind-app，具体人工创建步骤和验证命令见 tests/fixtures/xmind/manifest.md。

Open Questions

  • import --into 的 backup 语义应补实现还是收窄文档？当前更符合 全局 mutation 规则的方向是给 import --into 增加 --backup，同时保持 import --output 无 backup。
  • diff 的最终用户输入形态仍需在实现前确认：当前文档只有单 workbook 参数，后续应明确是 self-diff、workbook-vs-workbook，还是 patch preview 辅助命令。

Slice #14: Mutation E2E Coverage

  • Source Manifest: GitHub issue #14, parent PRD #1, docs/prd/1/implementation-notes.html, docs/technical/e2e-test-plan.md, tests/fixtures/xmind/manifest.md, docs/reference/commands/add.md, docs/reference/commands/set.md, docs/reference/commands/delete.md, docs/reference/commands/move.md, docs/reference/commands/copy.md, and docs/reference/mutation-semantics.md.
  • 决策：mutation E2E 覆盖只扩展测试和测试辅助方法，不改变 CLI 行为；所有 apply 用例都写临时 fixture 副本、写后 validate，并断言 committed fixture 源文件字节保持不变。
  • 决策：backup 断言比对备份文件内容等于变更前的临时 workbook 字节，同时检查 .xmind-backups 路径谓词。
  • 风险：当前 set 多字段单次调用只应用首个字段；本 slice 按当前稳定 行为用多次 set 调用覆盖每个 editable field，未在覆盖 slice 中扩大 应用语义。
