Current Baseline

  • 当前 CLI 是单 binary Rust package，公开入口由 clap subcommands 驱动；JSON envelope、错误码、退出码和 candidate 诊断是 agent contract 的稳定核心。
  • 读命令、sheet/topic selector、query、compact JSON、单点 mutation、 backup/restore、import/export、topic image 和 asset export 已有代码与 CLI 测试覆盖。
  • 已实现的写路径使用候选文件校验后替换，并保留未知 JSON 字段和未知 package entries；dry-run 不写文件。
  • Tree input 支持 YAML/JSON 与 Markdown frontmatter、heading/list/ordered list、task list、hybrid outline 和 note mapping；Markdown inline metadata 仍是明确拒绝，而不是部分支持。
  • Patch engine 已覆盖 dry-run working copy 规划、apply 写回、operation-indexed diagnostics、alias normalization、conflict detection，以及文档化 patch ops。patch --apply 现在会在所有操作规划成功后一次性写回 workbook。
  • 文档同步测试覆盖 help surface、schema docs、可运行示例、错误码和若干 stale CLI surface；其中可运行文档示例现在只执行明确标记为 bash e2e 的 fenced block，普通 bash 示例仍为说明性文本。它们不能替代逐命令行为验收。
  • CI workflow、security job、release build smoke、completion、installation docs、install script 和 changelog 均已存在；本地质量门仍以 ./scripts/quality-gate.sh 为准。
  • Canonical remote 已确定为 git@github.com:ivan-94/xmind-cli.git，该 GitHub 仓库已存在且为 public；正式 issue tracker 切换为 GitHub Issues。
  • E2E 定义为用户维度测试：基于真实 .xmind 文件覆盖所有命令和用户可见分支； 第一版使用 Rust integration test runner，release 只做薄 smoke。

Issue #34: Patch Apply and Safe Writes

  • Source Manifest: GitHub issue #34, the Obsidian real-workbook editing failure, the minimal repro snippets recorded in issue #34, src/app/patch.rs, src/app/mod.rs, src/app/validate.rs, src/infra/xmind/encode.rs, docs/reference/mutation-semantics.md, docs/reference/commands/patch.md, and docs/reference/patch-operations.md.
  • 修复：patch --apply 的 selector 解析不再与 dry-run 漂移； 已被 planner 接受的 id: / path: selector 必须在 apply 阶段作用到同一 working copy 目标，不能静默 no-op 后仍返回 applied: true。
  • 决策：topic id 生成抽成共享 allocator，先收集 workbook 已有 id，再为新增 topic 分配唯一 id。非 ASCII 标题会使用稳定 fallback 并追加后缀，避免中文标题批量生成时重复为 topic-patch。
  • 修复：写入层候选文件校验改为复用 xmind validate 的结构校验。候选 workbook 即使可 decode，只要存在 duplicate topic id 等结构错误，也会返回 validation_failed 并保留原文件。
  • 权衡：本轮不修改外部 xmind-cli skill，也不新增用户命令； 只让既有 patch/write 契约变为真实可靠。
